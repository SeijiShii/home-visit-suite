# 網羅管理

## 網羅活動データ

- 区域親番単位で「網羅活動」データを持つ
  - チェックアウトデータ（区域単位）を集約した上位データ
  - 網羅活動は AvailablePeriod（チェックアウト可能期間）と紐づく
- 作成・管理権限
  - 網羅活動データは編集メンバーが AvailablePeriod 作成時に自動生成される
  - 編集メンバーすべてに編集権限がある
  - 監査ログには AvailablePeriod の作成・編集・削除が記録される（`07_通知と申請.md`）
- 完了パーセンテージ
  - 実体完了パーセンテージ：全区域のチェックアウト完了状況・訪問記録から算出
  - ステータス上の完了パーセンテージ：運用上の恣意的な完了判定
    - 例：実体は50%だがステータスとして完了とする場合がある
  - 理想は全区域の網羅完了をもって区域親番の完了だが、運用上は恣意的に完了させることもできる

## 区域単位の進捗指標

網羅管理は区域単位の進捗指標も保持する。ダッシュボードや区域一覧で表示される進捗バーはこの値のエイリアス。

- 既定の指標：**区域内の場所（戸建て・部屋を独立カウント）に対する訪問記録あり場所の比率**
  - 「訪問記録あり」とは、当該場所を対象とした `VisitRecord` が1件以上存在することを指す（結果を問わず）
  - 同じ場所への複数訪問は重複カウントせず、場所単位で「あり／なし」の二値で評価する
  - 集合住宅は各部屋を独立した場所として個別にカウントする
- 期間スコープ：`AvailablePeriod` 単位で集計する
  - 区域単位進捗は「特定の AvailablePeriod 内に作成された訪問記録」の母集団で評価する
  - ダッシュボードは「現在時刻が含まれるアクティブな AvailablePeriod」の進捗を一律表示（`10_画面設計.md` ダッシュボード節参照）
  - 過去・未来の AvailablePeriod 別進捗は網羅管理画面（`/coverage`）で参照する
- ステータス内訳（会えた／留守／空き家／訪問拒否など）の重み付け表示は網羅管理画面で別途行う（区域単位進捗の基本指標は二値ベース）
- 計算ロジックや更新タイミングの詳細は実装フェーズで具体化する。**この指標を単一ソースとし、ダッシュボード等の他画面からはこの値を参照する**

## 進捗管理

- チェックアウトデータ・訪問記録を集計
- AvailablePeriod 単位で網羅状況を確認できる
  - 例：　現在の AvailablePeriod でいくつの区域親番、全体の何パーセント網羅したか
- 地図上で区域親番ごとの網羅頻度などをヒートマップ表示できる

## チェックアウト可能期間（AvailablePeriod）

編集メンバーが活動戦略として「いつ・どの範囲を活動対象にするか」を定義するオブジェクト。チェックアウトと訪問記録の親概念であり、網羅進捗集計の母集団境界となる。

### データモデル

```
AvailablePeriod（チェックアウト可能期間）
├── id, name, startDate, endDate
├── tags[]（AvailablePeriodTag への参照、複数）
└── parentAreaIds[]（対象区域親番リスト、複数）

AvailablePeriodTag（チェックアウト可能期間専用タグ）
├── id, name, color
└── （メンバータグとは別概念。混用しない）

Checkout
├── availablePeriodId（NOT NULL）
├── personInChargeId, checkedOutById
├── status（pending|active|returned|complete|force_closed）
└── ...

VisitRecord
├── checkoutId（NOT NULL）
└── （AvailablePeriod は Checkout 経由で導出）
```

### 基本性質

- AvailablePeriod は単一オブジェクト（区域親番との 1:1 ではなく、複数の区域親番を含む1つの設定）
- **時間的重複不可**: 同時に複数の AvailablePeriod がアクティブになることはない
- **承認フロー無し**: 編集メンバーが自由に作成・編集・削除できる（監査ログには全操作が記録される）
- 親概念として `Checkout` を子に持つ。アクティブな AvailablePeriod が存在しない時期はチェックアウト不可（クールダウン期間）

### 編集制約（段階的ロック）

| 状態 | 判定 | 編集可能項目 |
|---|---|---|
| 開始前 | `now < startDate` | 全項目（期間・対象区域親番・タグ・名前） |
| 活動中 | `startDate <= now <= endDate` | 終了日の **延長** のみ／対象区域親番の **追加** のみ／タグ |
| 終了後 | `endDate < now` | タグのみ（過去記録の不変性確保） |

- 活動中の **終了日短縮** は不可（既存チェックアウト・訪問記録への影響を防ぐ）
- 活動中の **対象区域親番削除** は不可（同上）
- 終了後の編集禁止により、過去記録の集計母集団が不変となる

### アクティブ判定

- システムは `startDate <= now <= endDate` を満たす AvailablePeriod を「アクティブ」とみなす
- 明示的な「開始」「終了」ボタンは持たず、機械的に判定する
- 編集メンバーが「今すぐ開始したい」場合は開始前状態で `startDate` を現在時刻に編集することで即時アクティブ化

### 期間終了時の挙動（強制クローズ）

- AvailablePeriod の `endDate` 到来時、当該期間に紐づく未完了（`pending` / `active`）チェックアウトはすべて **強制クローズ** 状態（`force_closed`）に遷移する
- 強制クローズされたチェックアウトに紐づく未失効の招待もすべて失効する
- これにより「区域がリセットされる」セマンティクスを担保（次の AvailablePeriod は新規チェックアウトから開始する）
- 強制クローズ前の訪問記録は当該チェックアウトに紐付いたまま保持され、過去記録ビューから参照できる

### 過去記録の参照

- 訪問記録は所属チェックアウト経由で AvailablePeriod に紐付く
- 過去 AvailablePeriod を `/coverage` 画面で選択すると、当時の達成率・区域別進捗・訪問記録一覧を参照できる
- 物理削除は行わない。テーブル分離もしない（同じ `visit_records` テーブルを `availablePeriodId`（経由）で絞り込む）

### AvailablePeriodTag（専用タグ）

- AvailablePeriod を分類するためのタグ（メンバータグとは別概念、共用しない）
- 用途例: 「春期キャンペーン」「強化エリア」「お試し運用」など活動戦略の分類
- 管理権限: **編集メンバー以上**（AvailablePeriod の作成者と同じ権限）
  - 既存タグからの選択 + 新規作成のその場入力（メンバータグと同じ UI 方式）
  - タグ削除時は「このタグを使っている期間が N 件あります」と確認ダイアログを表示
- タグ名は最大16文字、同名重複不可
- タグには色を設定できる（自動割当 + 手動変更可）
- 1つの AvailablePeriod に複数タグを付与可能

## 進捗把握

- AvailablePeriod の開始日・終了日に基づいて進捗を追跡する
- アクティブな AvailablePeriod の進捗はダッシュボードで一律表示
- 過去・未来の AvailablePeriod は `/coverage` 画面で参照する
