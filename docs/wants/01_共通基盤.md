# 共通基盤

## データ構造方針

- 全てのデータは木構造とする
- データの競合解決（同期・マージ）はLinkSelfのカバー範囲とする

## 用語定義

- 本仕様における「区域」は運用上の最小単位（枝番レベル）を指す
  - 正確には区域とは枝番の集合だが、メンバーが主に扱うのは枝番レベルであるため「区域」と呼称する
- 枝番の集合としての上位概念は「区域親番」と呼ぶ

## アプリの関係

- **単一 PWA + ロール別 UI**（2026-07-07 全面 PWA 化決定）。管理・編集向け機能と活動メンバー向け機能は同一アプリ内で権限ゲートにより出し分ける
- 管理・編集ロールの UI は活動ロールの UI の上位互換である（上位ロールは下位を包含）
  - 管理・編集ロールは訪問記録の閲覧・編集も可能
  - 管理・編集ロールの地図は編集可能、活動ロールの地図は閲覧・訪問記録用
  - 活動メンバーは管理・編集系画面にアクセスできない（権限ゲート）

## 実行環境

- **単一 PWA として全プラットフォームのブラウザで動作させる**（2026-07-07 決定。動機: ストア審査を経ずに配布・更新するため）
  - デスクトップ: Windows / Mac / Linux のモダンブラウザ
  - モバイル: iOS Safari / Android Chrome（ホーム画面追加でアプリとして利用）
- 旧構成（管理: Wails デスクトップアプリ / 活動: モバイルネイティブ）は廃止。Wails 版は新規開発凍結・段階的廃止（React 資産は PWA へ移植）
- ブラウザ実行の前提制約
  - LinkSelf はブラウザ向け TypeScript 実装（Go 実装とワイヤ互換の第二実装）を使用する（`11_LinkSelf拡張要望.md`）
  - ブラウザピアは外部からの着信を受けられないため、常時稼働ノード（リレー／ブートストラップ／メールボックス）が必要
  - バックグラウンド実行はゼロ（タブ／PWA を閉じると完全停止）。前景起動時に高速差分同期するライフサイクルを前提とする
  - オフライン対応は Service Worker（GSI タイルキャッシュ等）+ OPFS 永続化で設計する

## データインフラ

- LinkSelfを使用
  - https://github.com/SeijiShii/link-self
  - 完全サーバーレス
    - データはLinkSelfグループ外に出ることはない
    - ブラウザピアが必要とする常時稼働ノードは E2E 暗号化された転送のみを担う「ただの土管」であり、内容を読めない。この原則を破らない
- 管理メンバーと活動メンバーは同じグループに所属し、ロールが異なる

### ストレージ（LinkSelf MyDB / SQLite3）

- LinkSelf の `MyDB` を経由して SQLite3 にデータを永続化する
  - SQL（`Exec/Query/QueryRow/Migrate`）と KV（`Put/Get/Delete/List`）の両 API を持ち、書き込みは透過的に同期される
  - DB ファイル配置は LinkSelf 側で `<dataroot>/<DID>/suites/<SuiteID>/data.db` に自動配置（`Config.SuiteID = "jp.home-visit-suite"`）
- PWA では LinkSelf TS 実装が sqlite-wasm + OPFS 上に同等の `MyDB` API を提供する（旧 Wails 版は go-sqlite3 で単一プロセスアクセス前提）
  - 複数タブからの同時アクセスは単一アクセサに直列化する（Web Locks / SharedWorker 等、方式は LinkSelf TS 実装側で決定）
- スキーマは起動時に `MyDB.Migrate` で適用する
- **暫定ブリッジ（LinkSelf TS 実装完成まで）**: 現状は InMemory リポジトリ + localStorage 永続で動作させる。runtime（`createInMemoryServices({ persist: true })`）では全ドメインデータ（領域・区域・場所・チェックアウト・網羅・通知）と個人設定（言語・AI プロバイダ/キー/モデル・同意）を localStorage に write-through 永続化し、再読み込みでも保持する。テストは `persist` 省略でインメモリのまま。dev の疑似ユーザー群は毎起動シードのため非永続だが、**自分の identity（`hvs.identity`）だけは localStorage に永続**し、起動時に自己ユーザーを UserRepository へ復元する（「自分の ID の作成と保管」参照）。LinkSelf 導入時に本リポジトリ層を差し替える（API キー・秘密鍵等の平文保存も暗号化ストレージへ移行）

### 同期スコープ（SyncScope）

各テーブルは `SetSyncScope` で同期範囲を指定する。

| スコープ | 対象テーブル | 同期範囲 |
|---------|-------------|---------|
| `ScopeNetwork` | regions, parent_areas, areas, places, map_*, users, member_tags, available_periods, available_period_tags, available_period_parent_areas, checkouts, checkout_invitations, visit_records, visit_record_edits, coverages, requests, invitations, notifications, audit_log | LinkSelf ネットワーク内全メンバー |
| `ScopeDevice` | personal_notes, personal_tags, personal_tag_assignments, my_settings, **devices** | 同一ユーザーの端末間のみ |
| `ScopeLocal`（同期しない） | 端末固有で共有すべきでない個別設定 | その端末のみ（非同期） |

- **デバイス登録簿（`devices`）は `ScopeDevice`（同一ユーザーの端末間で同期）**。端末の追加・改名・削除が自分の全端末へ反映され、廃棄・誤登録した端末を別端末から一覧・削除できる（`個人デバイスの管理`）。暫定 localStorage 実装は M5 でこの `devices` テーブルへ移行する
- **同期タイミング**: 書き込みは MyDB 経由で透過的に伝播する。前景かつオンライン中は変更時にほぼ即時、相手がオフラインならメールボックス（store-and-forward）に預け、その端末の次回前景起動の差分同期で受信する（`実行環境`「前景起動→高速差分同期→graceful stop」）。したがって**デバイス登録・削除や設定変更も“変更時”に同期対象**になる（起動時のみの一括同期ではない）
- **端末ローカル（`ScopeLocal`・非同期）**: 端末固有で共有すべきでない個別設定は同期しない。同期の要否は設定項目ごとに判断する（デバイス登録簿は同期必須、端末固有の UI 設定等は端末ローカルでよい）
- App 内のメンバーグループ（旧 `org_groups`）概念は廃止済み。ロール（管理者・編集メンバー・活動メンバー）とメンバータグ・AvailablePeriod タグでメンバー分類は表現する
- Topic ベースのサブスクリプションでトラフィック最適化（活動メンバーは自分が関与する領域・区域の topic のみ購読）

### データ移行

- 初回起動時に旧 `~/.home-visit-suite/data/*.json`（JSONFileRepository 時代の遺産）が存在すれば MyDB へインポートし、成功時に `.migrated` マーカーを置く

### 自分の ID（identity）の作成と保管

- ユーザーの識別子は LinkSelf の DID（`did:key` 形式）とする。LinkSelf TS 実装 `@linkself/core` の `generateIdentity()` が Ed25519 鍵対と DID を生成する（Go 実装とバイト互換: `0xed` + 32byte 公開鍵を base58btc + `z` 接頭辞）
- **初回オンボーディング**: ローカルに identity が無い初回起動時はオンボーディング画面を出す。表示名を入力して「はじめる」で新しい identity を生成し、自分の User レコードを作成して入室する。以後の起動は保存済み identity をロードして直接入室する
- **秘密鍵の保管（暫定）**: 現状は identity（`did` / 秘密鍵シード / 表示名 / ロール）を `localStorage`（キー: `hvs.identity`）に保存する。LinkSelf 本統合（M5）時に WebCrypto 非抽出鍵 + OPFS の安全ストレージへ移行する（API キー等と同様の秘匿情報として扱う）
- 起動時、保存済み identity があれば（毎起動シードの）UserRepository へ自分の User を upsert して自己ユーザーを復元する
- 自分の DID は招待・通知の宛先として使う（Go 版 `Client.NodeInfo` 相当は TS では `client.did`）

### 端末ペアリング（同一 ID の別端末追加）

- 同一ユーザーの別端末（PC で作成した ID にスマホを追加する等）は、LinkSelf のペアリング（`@linkself/core` の `createToken` / `PairingSession` / `complete` / `exportPrivateKey` / `importIdentity`）で追加する。モデルは**同一 DID の秘密鍵フルコピー**（子鍵ではなく、両端末が同一 DID を持つ）
- **チャネル（暫定・URL 方式）**: ネットワーク越しの鍵配送は LinkSelf 側が未実装のため、当面はオフラインで成立する **URL を載せた QR** を用いる。既存端末（例: PC）は設定画面「デバイス」でペアリング用トークン（`{secret, expiresAt}`、TTL 数分）と鍵素材を含む **アプリの URL（`/pair`）** を QR として表示する
  - **アプリ内カメラでのスキャンは行わない**。新端末（例: スマホ）は OS のカメラアプリで QR を撮影する、または URL をブラウザに直接入力することで、アプリ（`/pair`）にリダイレクトされ、同一 identity を復元して個人デバイス登録が完了する
  - **鍵素材は URL フラグメント（`#/pair?d=...`）に載せる**。フラグメントはサーバーへ送信されないため秘匿レベルは QR/localStorage と同等を保つ。取り込み後はフラグメントを履歴から除去する（`history.replaceState`）
  - URL のベースは既定で実行時オリジン（`window.location.origin + BASE_URL`）を用いる（本番は自動で正しい）。`VITE_PAIRING_BASE_URL` で正規の公開 URL に上書きできる（localhost からスキャンできない開発時、プロキシ/独自ドメイン背後など）
  - カメラ・リダイレクトが使えない場合の手入力（URL/コード貼付）フォールバックをオンボーディングに用意する
- **冪等性**: `/pair` URL を **既に自分の ID が登録済みの端末**で開いた場合は、追加登録せず登録済み ID でそのままアプリを開く（payload は無視）。未登録の端末でのみ登録処理を行う
- **個人デバイスの管理（設定画面）**: 設定画面「デバイス」で、自分の ID に紐づくデバイスを管理する
  - 各デバイスは `deviceId`（端末固有のランダム ID）とラベルを持ち、`userId`（自分の DID）に紐づく（`ScopeDevice` のデバイス登録簿）
  - ラベル編集と、**当該デバイス以外の削除**（誤登録・端末廃棄時）ができる
  - **当該デバイス自身は削除できない**（設定画面から自分の登録を解除する導線は設けない。何が起きるか不明瞭で誤操作の温床になるため）。不要な端末は、残す別端末の一覧から削除する
  - **削除の意味**: 削除した端末は同一ユーザーのデバイス集合（同期ロスター）から外れ、以後その端末とはデータ同期しない。ただし鍵は端末に残るため、**改めてペアリング URL を渡せば再登録（再同期）できる**（削除＝ロスターからの除外であって、恒久 BAN や鍵失効ではない）
  - **当面の制約**: デバイス登録簿は暫定で localStorage 保管のため、他端末の一覧表示・削除の伝播は LinkSelf 同期（M4–M5）待ち。今は自端末の表示・ラベルまでが機能し、M5 で同期リポジトリ（`devices` テーブル）へ移行すると他端末の一覧・削除（＝ロスター除外）が反映されるようになる（UI に明示する）
- **同期の制約（当面）**: 端末を紐付けても、端末間の実データ同期は LinkSelf の常時稼働ノード／ネットワーク実装（`11_LinkSelf拡張要望.md` M4–M5）待ちのため当面動かない。各端末のローカルデータは別々のまま同期は将来 M5 で有効化される（この旨を UI に明示する）。紐付け済み端末は M5 導入時にそのまま同期対象になる
- ネットワーク作成・メンバー招待・脱退は LinkSelf の `Network` API で管理する

## アプリ設定画面

- アプリに「設定」画面 (`/settings`) を持つ（全ロール利用可）
- 設定値はユーザースコープ（= LinkSelf 個人設定、ScopeDevice、同一ユーザーの端末間で同期）で永続化する
- 初期の設定項目
  - 言語切替（ja / en）。従来サイドバーに置いていた切替は設定画面に統合する
  - ヘルプ表示リセット（個別に「表示しない」にしたツールチップを一括再表示）
  - 区域詳細編集の隣接半径（km、既定 2.5、キー: `ui.areaDetailRadiusKm`）
  - **AI 地図取り込み用 API キー**（`03_地図機能.md`「AI による区域地図作成」で使用）
    - プロバイダ（既定: Anthropic、キー: `ai.provider`）と API キー（キー: `ai.apiKey`）を登録する
    - API キーは秘匿情報。個人設定（ScopeDevice、E2E 暗号化、同一ユーザーの端末間同期）に保存し、UI ではマスク表示（末尾数桁のみ）する
    - 未登録時は区域編集画面の「AI で地図を取り込む」導線を不活性表示する
    - 入力欄には「キーの発行元・課金はユーザー自身の契約」である旨の注記を添える
- 追加の設定項目は必要に応じてここに集約していく

## 言語・ローカライゼーション

- UI 言語は `ja` と `en` を最初から両方用意する
- 言語設定はユーザースコープ（LinkSelf 個人設定、キー `ui.locale`）で保存する
- 起動時のちらつき防止のため、前回選択した言語を `localStorage` にミラー保存しておき、起動直後の描画はそれを用いる
  - 並行して LinkSelf から取得し、差分があれば切り替える
- 旧実装の `localStorage` locale キーがあれば初回起動時に LinkSelf へ移行する

## ツールチップ基盤（共通 UI）

- 画面右上に表示するツールチップ型のヘルプ基盤を共通で提供する
- i18n キー命名規則: `tips.<画面>.<動作>` (例: `tips.map.polygon.startDraw`)
  - 将来の他画面追加に備え、汎用的な基盤として設計する
- 振る舞い
  - 新しいメッセージは右上にスライドダウンで出現し、約 5 秒後にフェードアウト
  - 連続表示は 1.5 秒間隔のキューで順次投入
  - 同時表示は最大 5 件、超過時は最古から即時消去
  - 新しいメッセージは先頭に積まれ、既存は下へ押し下げる
  - 同一キーが既に表示中の場合は重複投入しない
  - 各メッセージに「このメッセージを表示しない」リンクがあり、クリックで該当キーを永続的に非表示化
- 非表示化したキーは LinkSelf 個人設定 (`ui.hiddenTipKeys`) に保存
- 設定画面の「ヘルプ表示をリセット」で一括解除可能
