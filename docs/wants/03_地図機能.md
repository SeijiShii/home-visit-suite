# 地図機能

## 画面構成

- 編集メンバー向けには「区域編集」画面（旧称: 区域地図）を提供する
  - ポリゴンの作成・編集・紐付け、区域親番/区域の編集を行う
  - 右サイドバー（区域一覧 / ポリゴン一覧タブ）は幅可変で、開閉ボタン（chevron）で折りたたみ・展開できる。折りたたみ時は地図を残り幅いっぱいに広げ、細い縦レールに展開ボタンだけを残す
  - 狭幅ビューポート（767px 以下）では**区域編集画面・領域管理画面を提供しない**（ナビゲーション項目を非表示にする。2026-07-16 追加。ポリゴン編集・領域編集はスマホの画面幅では成立しないため、広い画面での利用を前提とする）
- 場所（住宅情報）の閲覧・編集・訪問記録は「**訪問記録画面**」に統合する（**2026-07-14: 場所編集専用画面〔区域詳細編集〕を廃止**し、訪問記録画面が兼ねる）
  - 詳細仕様は `08_活動メンバー向けアプリ.md` の「訪問記録画面」節を参照
  - 場所の**追加**は全ロール・全端末で直接可能。**削除・移動・情報修正の直接操作は「編集メンバー以上 × 非タッチ端末」のときのみ**提供し、それ以外は申請とする（`07_通知と申請.md`「場所操作の権限」）
  - タッチ端末の判定は `matchMedia("(pointer: coarse) and (hover: none)")`（タッチ主体端末＝スマホ・タブレット。マウス接続のタッチラップトップは非タッチ扱い）
- 区域編集画面の中から当該区域の訪問記録画面に遷移できる（後述）

## 地図の初期表示位置

地図を表示する画面（区域編集画面・訪問記録画面）の初期表示位置は以下の優先順で決める（2026-07-17 追加）:

1. **前回の表示位置**: 地図操作（moveend）のたびに中心・ズームをローカル保存し、次回表示時に復元する（保存は地図画面間で共有）
2. 保存がない初回は **GPS（Geolocation API）の現在地**。取得は非同期のため、まず下記フォールバック位置を表示し、取得成功時点でまだ表示が動いていなければ現在地へ移動する
3. GPS が使えない場合（非対応・権限拒否・タイムアウト）は**東京駅周辺**（35.681236, 139.767125、zoom 14）のまま

- 訪問記録画面は地点（区域）指定で開くため、表示直後に対象区域（全飛地の外接範囲）へフォーカスする（「場所の直接編集」節）。この区域フォーカスは GPS 現在地より優先され、後から GPS 取得が完了しても上書きしない

## 現在地マーカーと現在地への移動

地図を表示する画面（区域編集画面・訪問記録画面）共通（2026-07-17 追加）:

- **現在地マーカー**: GPS（Geolocation API）が利用できる場合、現在地に青ドットのマーカーと測位精度円をリアルタイム表示する（`watchPosition` 購読。地図画面の表示中のみ購読し、画面を離れたら解除する）
  - 自動購読は**位置情報権限が既に許可済みのときだけ**行う（Permissions API で判定）。権限未決定のユーザーに、画面を開いただけで許可プロンプトを出さない（プロンプトは下記ボタン押下時に出す）
  - マーカー・精度円はクリック不可とし、ポリゴン・場所マーカーの操作を妨げない
  - 権限拒否・非対応環境ではマーカーを表示しない（エラーは出さない）
- **現在地へ移動ボタン**: 地図右上に常設し、クリックで現在地へパンする
  - ズームは現状維持。ただし 15 未満のときは 15 へ引き上げる（広域表示のままではパンの意味がないため）
  - まだ現在地が取得できていない場合は単発取得を試み（このとき権限プロンプトが出得る）、成功したらパンし、以後のリアルタイム購読を開始する。失敗時は何もしない
  - 狭幅の訪問記録画面では右上の場所一覧オープンボタンと重ならないよう、右上の地図コントロール群を下にずらす

## 区域IDラベル表示

- 区域紐付け済みポリゴンには、ポリゴン内（頂点平均の中心）に**区域ID**（例: `NRT-001-05`）をテキスト表示する（2026-07-14 追加）
- 目的: 地図表示範囲を広くしたときに、どのポリゴンがどの区域かを地図上で識別できるようにする（ただし極端な広域ではラベルが重なるため非表示。下記ズーム閾値参照）
- 表示スタイル: 濃緑文字＋白縁取り。ラベル自体はクリック不可とし、下のポリゴンのクリック操作を妨げない（2026-07-17 補足: ポリゴンの親番塗り分けが多色化した後も、ラベルは濃緑のまま全色共通とする。「区域親番ごとのポリゴン塗り分け」参照）
- 未紐付けポリゴンにはラベルを表示しない
- 1 つの区域に複数の飛地ポリゴンが紐づく場合、**各ポリゴンの中心に同一の区域IDラベル**を表示する（2026-07-15 追加。離れた飛地がどの区域かを地図上で識別できるようにする）
- 表示は**ズームレベル 15 以上**のときのみ（それ未満では非表示。広域表示ではポリゴンが小さくなりラベル同士が重なって視認性を損なうため。閾値は実装定数。2026-07-17 追加、当初 14 → 実機確認で 15 へ引き上げ）
- 訪問記録画面（詳細モード）でも同様に表示する（対象区域＋表示中の隣接区域。2026-07-14 変更: 当初は非表示としたが、隣接区域の識別にも有用なため表示に変更）。ラベルはクリック不可のため場所マーカーの操作は妨げない

## 区域親番境界の強調表示

- 区域紐付け済みポリゴンの辺のうち、**区域親番の境目**にあたる辺を太線で強調表示する（2026-07-15 追加。地図上で親番グループのまとまりを識別できるようにする）
- 境目の判定（辺単位）:
  - 異なる区域親番の紐付け済みポリゴン同士が共有する辺 → 境目
  - 紐付け済みポリゴンが片側にしかない辺（親番グループの外周。反対側が未紐付けポリゴンまたはポリゴン無し）→ 境目
  - 同一親番内の区域同士が共有する辺 → 境目ではない（通常の細線のまま）
- 表示スタイル: 濃スレート色（`#334155`）の**実線の太線**を描画する（2026-07-16 変更。当初は半透明帯を輪郭の下層に敷いたが、GSI タイル上で視認しづらいため実線太線に置き換えた）。クリック不可とし、ポリゴン・場所マーカーの操作を妨げない
- 重なり順: 親番境界の太線は**区域の境界線（ポリゴン輪郭）より下層**に描画し、太線上でも区域同士の境界線が見えるようにする（2026-07-16 変更。当初は輪郭より上層としたが、太線が区域境界線を覆い隠すため、区域境界線を手前に変更）
- 区域編集画面・訪問記録画面（詳細モード）の両方に適用する
  - 訪問記録画面では表示中（対象＋隣接）ポリゴンの辺のみ描画対象。ただし境目かどうかの判定は非表示ポリゴンの紐付けも含めて行う（表示範囲外の同一親番区域と接する辺を誤って外周扱いしない）

## 区域親番ごとのポリゴン塗り分け

- 区域編集画面（地図画面）の**紐付け済みポリゴン**は、**区域親番ごとに有彩色の数色で**塗り分ける（2026-07-17 追加。親番境界の太線（線）に加えて面でも親番グループを識別できるようにする）
- **紐付け有無の色体系**: 区域編集画面は**未紐付け=灰色（無彩色）／紐付け済み=有彩色**で判別する（2026-07-17 改訂。旧: 未紐付け=青系×紐付け済み=緑系。「紐付くと色彩がつく」という直感的な対比にする）。未紐付けが無彩色になったことでパレットの色相制限は不要になり、**全色相の有彩色**を使える（2026-07-17 再改訂。当初は緑〜黄緑系限定だった）。無彩色・低彩度の色は灰色と紛れるため含めない
- 用意する色: 有彩色 8 色（green `#22c55e` / blue `#3b82f6` / amber `#f59e0b` / teal `#14b8a6` / lime `#84cc16` / cyan `#06b6d4` / rose `#ec4899` / purple `#a855f7`）。各色に選択時の濃色（`#166534` / `#1e40af` / `#92400e` / `#115e59` / `#4d7c0f` / `#155e75` / `#9d174d` / `#6b21a8`）を対で持つ。連続インデックスが色相環上で離れる順序とする（連番の親番は地理的に隣接しがちなため。mod 割り当てでは色7→色0 の折り返しも隣接対になるため、折り返しを含めて距離を確保する）
- 割り当て: 区域親番号の数値を色数で **mod** して決定する（例: `NRT-001` → 1 → 色1、`NRT-008` → 8 → 色0）。親番セグメントから数値が取れない識別子は親番キーの文字コード和で代替し、必ずいずれかの色に落ちる
- 紐付け済みだが区域IDが未解決のポリゴンは色0（従来の green）とする
- 未紐付けポリゴンは**灰色**（slate 系: 非選択 `#94a3b8` / 選択 `#475569`）。紐付くと色彩（パレットの有彩色）がつく（2026-07-17 変更。旧: 青系）
- 訪問記録画面（詳細モード）は輪郭色（対象=オレンジ／隣接=水色）は変更せず、**同じ親番色を非常に薄い塗りつぶし**として適用する（2026-07-17 追加。「場所の直接編集」描画ルール参照）
- 区域IDラベルは従来どおり濃緑文字＋白縁取りのまま全色共通とする（視認性優先。ポリゴン色への追随はしない）

## ポリゴンクリック操作

- ポリゴン**シングルクリック** → ポリゴン編集モードに入る（頂点ドラッグ可）
- ポリゴン**ダブルクリック** → 当該区域の**訪問記録画面**へ遷移する（紐付け済み区域のみ）
- ポリゴン**右クリック** → コンテキストメニュー
  - ポリゴン編集
  - 訪問記録（紐付け済みのときのみ活性。当該区域の訪問記録画面へ遷移）
- 空白クリックで選択解除（ポリゴンクリックはマップへ伝播させない）
- 区域一覧の三点メニューにも「訪問記録」を追加し、行ダブルクリックでも遷移できる

## ポリゴン描画（手動フリードロー）のスナップ

描画モード中のクリックは既存のポリゴンネットワークへスナップする（許容距離 20px、2026-07-14 明文化）:

- **既存頂点の近く** → その頂点を使用する（描画開始時: そこを起点に描画継続 / 描画中: 接続して描画完了）
- **既存線分の近く** → 線分をその点で分割して頂点を追加する（描画開始時: 追加した頂点を起点に描画継続 / 描画中: 接続して描画完了）。これにより既存区域の境界線上から隣接区域の描画を開始・完了でき、境界を共有できる
- どちらにも近くない → その座標に新規頂点を配置する
- **描画モード中はポリゴンのクリック選択を無効化**し、ポリゴン輪郭・内部のクリックも上記スナップ判定へ通す（通常時は「ポリゴンクリック操作」節のとおり選択が優先）
- マウス追従中はスナップ先（頂点、または線分上の最近点）へ赤いスナップインジケーターを表示する。最初の 1 点目を置く前も表示する

## 頂点ドラッグでの頂点統合（マージ）と退化ポリゴンの扱い（2026-07-18 追加）

編集モードで頂点をドラッグして別の頂点に重ねた（スナップ許容距離内で離した）とき、2 つの頂点を **1 つに統合（マージ）** し、ポリゴンの整合性を保つ:

- **隣り合う頂点への重ね合わせ** → 統合する（両者を結んでいた辺は消滅し、ポリゴンの頂点数が 1 減る）。従来は隣接頂点がスナップ対象外だったため、重ねると重複頂点・退化辺が残りポリゴンが破綻していた
- **ドラッグ中の吸着**（2026-07-18 追加）: ドラッグ中、他の頂点（同一ポリゴン内・隣接頂点を含む）との距離が**吸着しきい値**以内になったら、プレビュー（マーカーとポリゴン形状）がその頂点の位置に吸着し、統合される見た目を事前に示す
  - 吸着しきい値は通常のスナップ許容距離（20px）より狭い **12px**（実装定数）。一定の距離があるときは吸着せず、頂点を他の頂点の近くへ繊細に配置できる
  - ドラッグ確定時の**頂点統合の判定半径も同じ 12px** とする（吸着していないのに離した瞬間に統合される齟齬を防ぐ）。**辺へのスナップ（境界共有）は従来どおり 20px** のまま
  - 吸着した状態で離せば従来の統合の挙動（隣接=辺の畳み込み/非隣接=分割・退化削除・確認ダイアログ・紐付け補正）がそのまま適用される
  - **ロック済みポリゴンの頂点へは吸着しない**（ロック頂点とは統合できないため。吸着の見た目だけ出して統合されないと同座標の重複頂点が残る齟齬になる）
  - 辺スナップ（確定時）は、射影が辺の端点にクランプされる位置（端点の延長方向）ではスナップしない（端点と同座標の分割頂点・長さ 0 の辺という退化構造を作らないため。通常の移動として確定する）
- **隣り合わない頂点への重ね合わせ**（同一ポリゴン内・他ポリゴンとも）→ 統合する。同一ポリゴン内の統合ではくびれ（ピンチ）が生じ、ポリゴンが **2 つ以上に分割されることがある**
- **統合の結果、面積がほぼ 0 になる・面が成立しなくなるポリゴンは削除する**（例: 三角形の隣接 2 頂点を統合 → 面が消滅）。面を構成しなくなった辺・孤立した頂点も残さず掃除する
- **分割時の区域紐付けの引き継ぎ**: 分割で生じた面の 1 つは元のポリゴン ID を引き継ぎ、残りには新しいポリゴン ID が発行される。元のポリゴンが区域に紐付いていた場合、**新 ID のポリゴンも同じ区域へ紐付ける**（飛地として両方が元の区域に属する）
- **適用範囲**: 分割・消滅に伴う紐付けの補正（引き継ぎ・解除）は頂点マージに限らず、ポリゴンの分割・消滅を生むすべてのローカル編集操作（弦の描画による分割、交差解決、頂点削除・溶解、undo 等）に共通で適用する
- **削除の確認ダイアログ**（2026-07-18 追加）: 頂点ドラッグの統合でポリゴンが消滅する場合、「この操作によりポリゴンが削除されます。よろしいですか？」の確認ダイアログを表示する
  - OK → 削除を確定する（保存・紐付け解除もこの時点で実行）
  - キャンセル → 操作を取り消し（undo）、ドラッグ前の状態に復元する
  - 対象は頂点ドラッグ確定時のみ（頂点右クリックメニューからの削除など、削除意図が明示的な操作には出さない）

## 区域編集画面のアンドゥ・リドゥボタン（2026-07-18 追加）

- 地図（区域編集）画面に**アンドゥ（元に戻す）・リドゥ（やり直す）ボタン**を常設する
- 配置: 地図パネル**左下**のフローティングコントロール（左上のズームコントロール・操作ヘルプチップ、中央上部の描画/編集ツールバー、右上のベース地図切替・現在地コントロール、右下の地図帰属表示のいずれとも干渉しない位置）
- 取り消し対象はポリゴン編集操作（頂点移動・統合・描画・削除等）。実行不可のときはボタンを不活性表示する
- undo/redo で分割・消滅が起きた場合も「分割・消滅に伴う紐付けの補正」を適用する
- 確認ダイアログでキャンセルした操作は undo 済みとして扱う（リドゥで再実行した場合は確認なしで確定する）
- **確定済みの削除を undo した場合**、ポリゴン（幾何）は同一 ID で復元されるが、確定時に解除した区域紐付けは自動では復元しない（必要なら手動で再紐付けする。紐付け解除は確定時点でグループへ伝播済みのため）
- 確認ダイアログの表示中に他端末の編集受信でエディタが再構築された場合、保留中の操作は破棄しダイアログを閉じる（未保存のドラッグ操作自体が受信で消えているため。適用すると削除されないポリゴンの紐付けだけ解除する事故になる）

## 区域紐付けの無効ポリゴン ID 修復（2026-07-18 追加）

過去の不具合（上記マージ未対応による破綻等）の副作用で、削除済み・破綻済みのポリゴン ID が区域に紐付いたまま残ることがある。これを自動修復する:

- 地図画面のロード時に全区域の紐付きポリゴン ID をスキャンし、**無効な ID の紐付きを解除**する
- 無効と判定する条件: (a) ポリゴンがエディタに存在しない（削除済み）、(b) ポリゴンの面積がほぼ 0（操作時点で削除される前提のため、残っていれば過去の破綻の名残。しきい値は面列挙と同じ 1e-10 度² ≒ 約 1.2 m²）
- 修復は自動・サイレントに行う（ユーザー操作は不要）
- **誤解除の保護**（紐付き解除は共有データへの書き込みとして全メンバーへ伝播するため）:
  - 実行は地図画面のマウントごとに 1 回のみ（受信追従によるエディタ再初期化では再実行しない）
  - 条件 (a)「存在しない」の解除は、ローカルにポリゴンデータが 1 件以上取り込まれている場合のみ行う。P2P 同期がまだ届いていない端末では「存在しない」と「未着」を区別できないため、マップデータが空の端末はスキャンを見送る（面積ほぼ 0 の (b) は実データで破綻を確認できるため常に解除する）
  - 既知の残余リスク: 他端末の「描画→紐付け」直後に、紐付き（区域行）だけが先に届きポリゴン行が未着のタイミングでロードすると、その紐付けを誤解除し得る。頻度・影響が小さいため許容し、発生時は再紐付けで復旧する

## 場所の直接編集（訪問記録画面内）

旧「区域詳細編集モード」（専用画面）は廃止し、以下の仕様は**訪問記録画面内の直接編集機能**として提供する。直接編集（削除・移動・情報修正）が可能なのは**編集メンバー以上 × 非タッチ端末**のときのみ（前述「画面構成」）。

- 起動経路（3 つ、いずれも当該区域の訪問記録画面に遷移）
  1. 区域一覧の三点メニューから「訪問記録」
  2. 区域一覧の区域行ダブルクリック
  3. 地図上のポリゴンダブルクリック
- 起動条件: ポリゴン紐付け済みの区域のみ（ダッシュボードからの入口は `08_活動メンバー向けアプリ.md`「訪問記録画面」参照）
- **区域編集画面から遷移してきた場合のみ**、訪問記録画面の地図上に「区域編集に戻る」ボタンを表示する（ダッシュボード起点では表示しない。遷移元はナビゲーション状態で判別）
- 描画ルール（2026-07-14 改訂: 旧・緑系の濃淡は Google マップの地色と紛れて見づらいため配色変更。2026-07-17 補足: 区域編集画面はその後「区域親番ごとのポリゴン塗り分け」の有彩色パレットに変更）
  - 当該（対象）区域の輪郭: **オレンジ**（`#f97316`）太線。**常に最前面に描画する**（共有境界で隣接区域の線に上書きされない）。対象区域に複数の飛地ポリゴンが紐づく場合は**すべてを対象区域の輪郭として描画**する（2026-07-15）
  - その他（隣接）区域の輪郭: **水色**（`#38bdf8`）細線
  - 塗りつぶし: 区域親番ごとの塗り分け色（「区域親番ごとのポリゴン塗り分け」参照）を**極薄**（fillOpacity 0.08 程度）で敷く（2026-07-17 変更。当初は塗りつぶしなし。輪郭色は従来どおり対象=オレンジ／隣接=水色のまま）
  - 「隣接」の定義: 編集対象区域の中心から半径 N km 内に中心があるすべての区域
  - 飛地がある区域の「中心」は**全飛地ポリゴンを含む外接範囲（バウンディングボックス）の中心**とする（2026-07-15）。初期表示は全飛地が収まる範囲にフォーカスし、「地図を区域へ戻す」ボタンも同じ範囲へ戻す
  - 場所の追加・移動の「編集中の区域内」判定は、**いずれかの対象ポリゴン内**にあれば区域内とみなす（2026-07-15）
- ズーム制限
  - 詳細編集中は最小ズームレベルを制限し、半径 N km 程度が画面に収まる範囲を維持
  - N km は設定画面 (`/settings`) で変更可能（既定 2.5km、キー: `ui.areaDetailRadiusKm`）
- 場所操作（**直接編集権限があるときのみ。無い場合の操作は `08_活動メンバー向けアプリ.md`「操作仕様」参照**）
  - ポリゴン内右クリック → コンテキストメニュー「家を追加」「集合住宅を追加」
    - 「家を追加」選択後、入力ダイアログが開き「住所」「名前」を任意入力（空のまま保存可能）→ 保存で `Place` (`Type="house"`) を作成
    - 「集合住宅を追加」選択後、集合住宅用の入力ダイアログが開く（後述「集合住宅の追加・編集」節）
    - 5m 以内に削除済み場所がある場合は先に復元確認ダイアログ、その後に入力ダイアログを表示（**集合住宅追加時は復元確認なし**）
  - 場所アイコン右クリック → 「場所編集」「移動」「削除」
    - 場所編集: 戸建てと集合住宅で別のダイアログを開く
      - 戸建て (`house`): 現在の名前・住所を初期値にした編集ダイアログ（作成ダイアログと同一 UI）。保存で `Place.Label` / `Place.Address` を更新
      - 集合住宅 (`building`): 集合住宅編集ダイアログ（後述「集合住宅の追加・編集」節）
    - 移動: 選択直後からマウス追従（ボタンは押さない）。クリックで確定 / Esc キャンセル。移動中は地図ドラッグを無効化。集合住宅でも同じ挙動（部屋の `Coord` は移動しない）
    - 削除:
      - 戸建て: 確認ダイアログ → 論理削除
      - 集合住宅: 確認ダイアログ（「この集合住宅と N 部屋を削除しますか？」）→ **Building と全 Room を同時に論理削除（カスケード）**
  - 追加・移動の対象座標が**編集中の区域ポリゴン外**の場合は処理を中止し、画面上部に赤いエラーバナーを 4 秒表示する
    - メッセージ: 「場所の追加または移動は編集中の区域内でのみ可能です」
- 場所アイコン
  - 種別ごとに色を変えた円形（**house=青 `#2563eb`、building=オレンジ `#ea580c`**）
  - Phase 1 では Room 個別のアイコンは地図に表示しない（Room は座標 `(0, 0)` のダミーで保持、地図描画対象外）
  - 将来 Room を地図表示する必要が出た場合は別色（例: 緑）を割り当てる
  - 半径はズームレベル連動 (8〜14px)
  - モバイル環境でも無理なくタップ可能なサイズ
  - ホバー時にツールチップで `Label`（名前）を表示。未入力の場合は「名前なし」
  - 円形アイコンに **通し番号バッジ**を重ねて表示する（`Place.SortOrder + 1`、区域内で 1 始まり）
  - 場所一覧パネルで選択中の行に対応するアイコンは強調表示する
- 区域編集画面（親モード）では場所アイコンを**読み取り専用の灰色（不活性）表示**で重ねる（2026-07-16 改訂、従来は非表示。「区域編集画面での場所表示と番号再採番」参照）

## 集合住宅の追加・編集

- データ構造
  - 集合住宅は `Place` (`Type="building"`) と、その子として `Place` (`Type="room"`, `ParentID=<BuildingID>`) を複数持つ
  - Room の `Coord` は `(0, 0)`（ダミー。地図上には個別描画しない）
  - Room の `Label` は使用しない（空文字）。部屋番号は `Place.DisplayName` に格納する
  - Room の `SortOrder` は同一 Building 内の並び順（0 始まり）
  - Building は `Description` フィールドを持つ（任意）。建物全体の補足情報（注意事項、入口の特殊性、立入禁止情報など）を編集メンバーが記述する。訪問記録ダイアログ起動時に内容があれば上部に表示される（`08_活動メンバー向けアプリ.md` 参照）
- 作成ダイアログ (`BuildingEditDialog`、新規モード)
  - 入力項目
    - 住所（任意）
    - 名前（任意）
    - **Description**（任意、複数行テキスト）。建物全体の補足情報（注意事項など）。訪問記録ダイアログでは内容ありのときのみ上部に表示される
    - 部屋番号一覧
      - 各行: 部屋番号入力欄（空欄可）+ `×` 削除ボタン
      - 初期状態は 1 行（空欄）
      - 行数の最小は 1（最後の 1 行は `×` が無効）
      - 行の下部に `[+1] [+5] [+10]` ボタン（押下で空行を N 行追加）
      - 行の **D&D 並び替え** に対応
  - 保存処理
    - Building を 1 件 `savePlace` で作成
    - Building の戻り `id` を使い、Room を行数分 `savePlace` で作成
    - Room の `DisplayName` は入力値、`SortOrder` は行順で 0..N-1、`Coord` は `(0, 0)`、`Label` は空
    - Building の `SortOrder` は区域内の既存 Place 最大値 + 1
  - キャンセル
    - 入力内容は破棄し何も保存しない
- 編集ダイアログ (`BuildingEditDialog`、編集モード)
  - 作成ダイアログとほぼ同じ UI。既存 Room を `SortOrder` 昇順で行として表示
  - `Description` も既存値を初期表示し編集可能
  - 行操作
    - 新規追加行の `×`: 即座に行削除（確認なし）
    - 既存 Room 行の `×`: 確認ダイアログ（「この部屋を削除しますか？」）→ Save 時に `deletePlace` で論理削除
    - D&D 並び替え: 保存時に全 Room の `SortOrder` を行順で再採番
    - 部屋番号（`DisplayName`）編集: 保存時に `savePlace` で反映
  - 保存処理は差分適用（追加 / 更新 / 削除）を一括でサービス呼び出し
    - 追加行の部屋番号が同一 Building 内の論理削除済み Room と一致する場合は新規作成せず復元する（「場所の論理削除と訪問記録の紐付け／部屋（Room）の同番号復元」2026-07-17 追加）
- 集合住宅**訪問ダイアログ**からの部屋の追加・編集（部屋番号）・削除（タッチ端末含む全メンバー可）は `08_活動メンバー向けアプリ.md`「集合住宅訪問ダイアログ」を参照
- トリガー
  - 右クリックコンテキストメニュー「集合住宅を追加」→ 作成ダイアログ
  - 集合住宅アイコン右クリック → 「場所編集」→ 編集ダイアログ
  - 場所一覧パネルの集合住宅行ダブルクリック → 編集ダイアログ
- カスケード削除
  - Building の `deletePlace` 時、同じ `ParentID` を持つ全 Room（`DeletedAt == null`）も `DeletedAt` を立てて論理削除する
  - 確認ダイアログメッセージには対象部屋数を含める

## 場所一覧と訪問記録の一覧（訪問記録画面）

対象区域に属する場所の一覧に、場所ごとの訪問記録（日時・会えた・留守など）を併せて確認できる一覧 UI を訪問記録画面に設ける（2026-07-14: 旧「場所一覧サイドパネル」を拡張して統合）。

- 表示形式は**画面幅で切り替える**（権限ゲートのタッチ判定とは軸を分ける。レイアウトは画面の広さの問題のため）
  - **広幅**（768px 以上目安）: 右側の収納可能なサイドペイン。既定状態は「開」、幅は 320px 目安
    - 上部バー右端の chevron アイコンボタンで開閉する
    - 開閉状態は LinkSelf 個人設定に保存（キー: `ui.areaDetailPlaceListOpen`、端末間同期）
    - 閉じているときは地図が全幅に広がる（パネル部分は 0 幅）
  - **狭幅**（スマホ等）: 地図上の「一覧」ボタンから全面オーバーレイで開く（閉じるボタンで地図へ戻る）
- 訪問記録の表示
  - 各場所行に**直近の訪問記録**（結果＋日時）を表示する
  - 行をタップ／クリックで展開すると、当該場所の訪問記録一覧（日時降順）を表示する
  - 集合住宅行の展開では、子 Room の記録も部屋番号を併記して同一リストに表示する
- 表示対象
  - 対象 `areaId` に属する `Place` のうち `DeletedAt == null` かつ `ParentID == ""` のもの
  - **戸建て (`house`) と集合住宅 (`building`) をフラットに同一リストに表示**（`SortOrder` を共有、通し番号も通し）
  - Room (`Type == "room"`) は一覧パネルには表示しない（集合住宅の編集ダイアログ内で管理）
- 行表示項目（左から）
  - 通し番号バッジ（`SortOrder + 1`、1 始まり）
  - 種別アイコン（house=青、building=オレンジ）
  - 1 行目: `Label`（未入力時は「名前なし」）
  - 2 行目:
    - 戸建て: `Address`（小さめのフォント、未入力時は非表示）
    - 集合住宅: `🏢 N部屋` 形式で子 Room 件数（`DeletedAt == null` のみ）を併記。`Address` があれば続けて表示
- 並び順と通し番号
  - 並び順は `Place.SortOrder` の昇順
  - 通し番号 = `SortOrder + 1`（表示上のみの換算。永続化値は 0 始まり）
- 並び替え（ドラッグ＆ドロップ、**直接編集権限があるときのみ**）
  - 行を縦方向にドラッグして順序を入れ替えられる
  - 確定時、対象区域内のすべての場所に 0..N-1 の新しい `SortOrder` を再採番し、順次 `PlaceService.savePlace` で保存する（将来的にバルク API 検討）
  - 番号は並び替え完了時に即座に一覧と地図アイコンのバッジに反映される
  - アクセシビリティのためキーボード操作（上下矢印＋Space/Enter）にも対応する
- 初期 `SortOrder` の確定
  - 訪問記録画面の初回起動時、対象区域内のすべての場所の `SortOrder` が 0 の場合、**作成日時 (`CreatedAt`) の昇順**で 0..N-1 を採番し保存する
  - 以後、既存場所の `SortOrder` は削除・並び替え・**重複時の再採番**（「区域編集画面での場所表示と番号再採番」2026-07-16 追加）以外で変更しない
- 行クリック時の地図連動
  - 行（背景部分）クリック: パネル上で選択状態にし、**地図を当該場所の座標までパン移動**する（`map.panTo`、ズームレベルは維持）
  - 行内の三点メニュー等の操作要素は別途（クリックイベントは `stopPropagation`）
- 行ダブルクリック（**直接編集権限があるときのみ**）
  - 戸建て行: 「場所編集」ダイアログ（`AddPlaceInputDialog` 編集モード）を開く
  - 集合住宅行: 集合住宅編集ダイアログ (`BuildingEditDialog`) を開く
  - 直接編集権限がない場合、行ダブルクリックは記録一覧の展開と同じ扱い（編集ダイアログは開かない）
- 新規追加・削除との連動
  - 「家を追加」「集合住宅を追加」で `Place` が作成された場合、`SortOrder` は既存最大値 + 1 として末尾に追加される
  - 削除（論理削除）した場合、一覧から即時除外し、残りの場所の `SortOrder` は詰め直さない（番号の欠落は許容）
  - ただし次回並び替え操作時には全体を 0..N-1 で再採番する

## 場所の論理削除と訪問記録の紐付け

- 場所 (`Place`) は物理削除せず、`DeletedAt` を立てる論理削除
- 場所を追加・移動して確定する際、座標から半径 5m 以内に削除済みの場所がある場合、
  「過去のこの地点の場所の訪問記録と紐づけますか」確認ダイアログを表示する
- 「はい」を選んだ場合、新しい場所に `RestoredFromID`（旧 PlaceID への参照）を持たせる
- 訪問記録自体の付け替えは、訪問記録機能の設計時に対応する（Phase 1 ではフラグ保持のみ）

### 部屋（Room）の同番号復元（2026-07-17 追加）

部屋は座標を持たない（`Coord=(0,0)`）ため 5m ルールは適用できない。代わりに**部屋番号の一致**で復元する。誤って削除された部屋も、後で同じ部屋番号を追加すれば同一 `Place` として復活し、過去の訪問記録が自動的に再び紐づく。

- 部屋の**追加**時（集合住宅訪問ダイアログの部屋編集モード・集合住宅編集ダイアログのどちらの行追加でも）、同一 Building 内（同じ `ParentID`）に部屋番号（`DisplayName`）が一致する論理削除済み Room があれば、新規 `Place` を作らず既存 Room の `DeletedAt` を解除して**復元**する
  - 同一 `PlaceID` を再利用するため訪問記録は自動的に再紐付けされる（`RestoredFromID` は使わない）
  - 確認ダイアログは出さない（同一建物内の同一部屋番号は同一の部屋とみなせるため自動でよい）
- 部屋番号が**空欄**の追加は復元マッチングの対象外（常に新規作成）
- 一致する削除済み Room が複数ある場合は `DeletedAt` が最新のものを復元する
- 復元した Room の `SortOrder` は行順の再採番に従う（訪問ダイアログの部屋編集モードと集合住宅編集ダイアログは同一の部屋行 UI・差分適用を共有する。2026-07-17 統一）
- 部屋番号の**編集**（改名）で削除済み部屋と同じ番号になった場合は復元しない（追加操作のみが対象）

- 領域、区域親番、区域をポリゴンとして作成できる
  - 地図ポリゴン編集ライブラリ
    - https://github.com/SeijiShii/map-polygon-editor
    - レポジトリ作成者が同一なので不足する機能は追加可能
- 地図タイルはOpen Street Mapまたは日本国内向けには国土地理院地図を使用
  - OSMが理想だが、細かい住宅建物情報などが欠落しているので地理院地図を使用する
    - 参考デモアプリ
      - https://github.com/SeijiShii/map-polygon-editor-demo
      - 要件が絞り切れていないため、機能は非常に限定的
- ポリゴンの整合性検証（重なり・隙間の検出・防止）はマップポリゴンライブラリの責任範囲

## 地図プロバイダ（背景タイル）

- 地図の背景タイルの提供元（プロバイダ）は**サービス提供者がビルド/デプロイ時の環境変数で一元設定**する。全利用者の全地図表示で使う基盤であり、課金も提供者契約であるため、利用者の個人設定にはしない。設定画面には出さない
  - **GSI（既定）**: 無料・キー不要。日本国内の住宅建物情報が細かく、既定かつフォールバック先。タイル: `https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png`
  - **Google マップ**: Google Maps JavaScript API を利用。API キー必須
- 環境変数（`pwa/.env` 系。`VITE_` プレフィックスでクライアントへ露出）:
  - `VITE_MAP_PROVIDER`: `gsi`（既定）| `google`
  - `VITE_GOOGLE_MAPS_API_KEY`: Google Maps JS API キー（`provider=google` のとき必須）
  - 解決は `pwa/src/lib/map-config.ts` の `resolveBaseMapConfig()` に集約
- 実装方式: 既存のポリゴン編集・オーバーレイ資産は Leaflet 上に構築済みのため、Leaflet はそのまま維持し、Google は **`leaflet.gridlayer.googlemutant`** プラグインでベースレイヤーとして重ねる（Google の生タイル URL 直指定は利用規約違反のため不可）。Google Maps JS API は `<script>` 動的挿入で 1 度だけ読み込み、プラグイン本体は動的 import でコード分割する（GSI 利用時は一切読み込まない）
- API キーはブラウザキーとして露出する前提。**HTTP リファラ制限**（IP 制限は不可＝ブラウザ発信のため）＋ **API を Maps JavaScript API のみに制限** ＋ **予算上限**を推奨
- provider=google でもキー未設定・読み込み失敗の場合は **GSI にフォールバック**して地図を保つ（`MapRenderer.setBaseMap`）
- **地図/航空写真の切替**: Google 表示中のみ、地図右上に「地図」/「航空写真」トグル（Leaflet コントロール）を表示する。「地図」= roadmap、「航空写真」= hybrid（衛星＋道路・地名ラベルを重畳し、訪問時に道路名を残す）。GSI 表示時はトグルを出さない（GSI に航空写真は無いため）。ラベルは i18n（`map.baseMapRoadmap` / `map.baseMapAerial`）

## ポリゴン一覧での区域紐付け・紐付け解除

- **1 つの区域には複数のポリゴンを紐づけられる**（飛地対応。2026-07-15 変更、従来は 1 区域 1 ポリゴン）
  - データ保持は `Area.polygonIds`（ポリゴン ID の配列）。旧 `polygonId`（単一）は読み取り時に配列へ読み替える（互換移行）
  - 同一区域の全ポリゴンは表示・操作上対等に扱う（「代表ポリゴン」の概念は持たない）
- 各ポリゴン行の区域ラベルは、紐付け先区域の識別子に区域親番名を併記する（例: `NRT-001-05 加良部1丁目`）。区域親番名が未設定（空）なら識別子のみを表示する。区域親番名の設定は区域一覧（AreaTree）で行う（[02](02_領域と区域.md) 参照）。同一区域に紐づく複数行には同じラベルが並ぶ
- 名前併記により行が長くなるため、右サイドバー（一覧ペイン）の初期幅は区域親番名が折り返さない程度に広く取る（幅は引き続き可変）
- 区域と紐づいていないポリゴン
  - リンクアイコンボタン（鎖マーク）を表示
  - クリックするとダイアログが開く
    - ダイアログ内は区域一覧と同じツリービュー
    - ポリゴンと紐づいていない区域を選択できる
    - 紐づけ済みの区域はグレーアウトして不活性のまま、**行の右側に「飛地ポリゴンを追加」アイコンボタンを表示**する（2026-07-15 追加）。押下でこのポリゴンを当該区域へ追加紐付け（飛地）する
    - 区域クリック（未紐付け区域）／飛地追加ボタン（紐付け済み区域）のどちらでも「区域○○と紐づけました」というトーストが出てダイアログが閉じる
- 区域と紐づいているポリゴン
  - リンク解除ボタン（鎖カットマーク）を表示
  - クリックすると「区域○○との紐づけを解除しますか？」確認ダイアログ
  - 解除ボタンクリックで**当該ポリゴン 1 つのみ**解除する（同じ区域の他の飛地ポリゴンの紐付けは維持）

## 区域一覧（AreaTree）でのポリゴン紐付け表示と解除

- ポリゴンが紐づいている区域にはグリーンのポリゴンアイコンを表示（複数紐付けでもアイコンは 1 つ）
- ポリゴンアイコンの横に三点リーダーメニューボタンを表示
  - クリックすると「ポリゴン紐づけ解除」メニューが表示される
  - メニュー選択で確認ダイアログ → 解除ボタンで**当該区域の全ポリゴンを一括解除**する（ポリゴン単位の解除はポリゴン一覧側で行う）
  - 複数ポリゴンが紐づいている場合、確認ダイアログに「区域○○との紐づけ（ポリゴン N 件）をすべて解除しますか？」と件数を明記する。1 件のときは従来文言
- ポリゴン描画開始ボタンは区域一覧には表示しない（描画はポリゴン一覧側から行う）

## 住宅マーカーの区域帰属

- マーカー座標がポリゴン内にある状態をもって区域に所属する場所とする
  - ポリゴンの隣地に建物が建った場合などはポリゴンの編集が必要
- チェックアウト中にポリゴン外に建物を見つけた場合
  - チェックアウト中は地図アプリ上で「どの区域で活動中」という情報を持つので、作成した場所は当該区域（`areaId`）へ帰属させる
  - **場所の直接追加（ロングタップ経由）はポリゴン外でも可能**とする（直接編集の右クリック追加・移動の「区域内のみ」制約はロングタップ直接追加には適用しない。`08_活動メンバー向けアプリ.md`「場所の直接追加」）
  - 編集メンバーが他のポリゴンに帰属すると判断する場合は編集時に変更できる

## 区域編集画面での場所表示と番号再採番（2026-07-16 追加）

### 読み取り専用の場所オーバーレイ（灰色・不活性）

- 区域編集画面（地図画面）に、全区域の場所を**読み取り専用の不活性（disabled）アイコン**として重ねて表示する（従来は非表示。ポリゴン編集時に場所との位置関係を確認できるようにするため）
- 対象は一覧・バッジと同じ集合: `DeletedAt == null` かつ `ParentID == ""`（house / building。Room は地図描画対象外の既存仕様どおり）
- 表示は**ズームレベル 16 以上**のときのみ（それ未満では非表示。広域表示でポリゴン編集の視界を妨げないため。閾値は実装定数）
- アイコンは**灰色**（`#94a3b8`）の円形。不活性表示のため種別（house/building）による色分けはしない。**通し番号バッジ**（`SortOrder + 1`）は重ねて表示する
- クリック・右クリック・ホバー等には一切反応しない（場所の編集は訪問記録画面の直接編集で行う。既存仕様どおり）
- 描画・再判定のタイミング: 画面表示時、およびポリゴンの編集確定（編集終了）・紐付け/解除・削除後

### 区域に所属しなくなった場所の警告表示（赤灰色）

- 「住宅マーカーの区域帰属」の原則（マーカー座標がポリゴン内にある状態をもって所属）に照らし、**所属区域（`Place.areaId`）のどのポリゴン（飛地含む）にも内包されない場所**を**赤灰色**（`#b06a6a`）で表示する
  - 内包判定は各ポリゴンの**外周リングのみ**で行う（穴＝内側リングは考慮しない。訪問記録画面の「編集中の区域内」判定と同じ扱い）
- ポリゴン編集で区域が破綻し境界外に出た場所のほか、判定起因は問わない: ロングタップ直接追加でポリゴン外に作られた場所・ポリゴン未紐付け区域（ポリゴン 0 個 = 内包なし）の場所も同様に赤灰色となる
- **表示のみの警告**であり、データ（`Place.areaId` 等）は自動変更しない。解消は編集メンバーがポリゴンの修正、または訪問記録画面での場所の移動・帰属変更で行う

### 表示番号の重複と再採番

- 区域の再編・統合や端末間の同期マージにより、同一区域内で `SortOrder`（表示番号）が重複し得る
- 区域編集画面が場所データを読み込んだ際、区域単位で重複を検出したら、その区域の対象場所全件を**「上（北）から順に、同緯度なら左（西）から」**若い番号になるよう 0..N-1 で再採番して保存する
  - ソートキー: 緯度の降順 → 経度の昇順 → PlaceID 昇順（完全な決定性の担保）
  - 決定的・冪等（同じ入力なら常に同じ結果。複数端末が同時に修復しても LWW で同一結果に収束する）
  - 変更のあった場所のみ保存する（無変更の書き込みをしない）
  - **全件が `SortOrder == 0` の未初期化状態は「重複」として扱わない**。初回採番は既存仕様（「場所一覧と訪問記録の一覧」の CreatedAt 昇順初期採番、訪問記録画面の初回起動時）に委ねる（初期採番規則と幾何再採番が競合しないため）
- 重複時の再採番は手動並び替え（D&D）で作られた順序を破棄する。重複した時点で従来の順序は一意性を失っており、幾何順への正規化を優先する（「既存場所の `SortOrder` は削除・並び替え以外で変更しない」原則の明示的な例外）
- 修復（書き込み）を行うのは区域編集画面（編集メンバー以上のみアクセス可）だけとする。訪問記録画面では重複が見えても自動書き換えしない（活動メンバー端末から共有データを自動修復しないため）

## ポリゴンの同時編集

- ポリゴンネットワークは頂点・辺・ポリゴンをエンティティ単位で LinkSelf MyDB に格納する
  - テーブル: `map_vertices` / `map_edges` / `map_polygons`（いずれも `ScopeNetwork`）
  - 旧来の「ネットワーク全体を 1 つの JSON として読み書き」する方式（`map_networks` 単一 BLOB）は廃止
- map-polygon-editor の `StorageAdapter` はレコード単位の `putVertex` / `deleteVertex` / `putEdge` / `deleteEdge` / `putPolygon` / `deletePolygon` を持つ
  - 各操作は即時にストレージへ反映し、`saveAll()` 一括保存は廃止（明示 flush 用途のみ残す）
- 他メンバーからの変更は `onRemoteChange(handler)` で受信し、エディタの `applyRemoteChange(ChangeSet)` で内部状態と UI に反映する
- 競合解決は LinkSelf の Last-Write-Wins（タイムスタンプ比較）に委ねる
  - 編集メンバーは通常異なる領域・区域を担当するため、同一エンティティへの同時操作は稀との前提
  - 辺の同時 split / delete のように整合が崩れた場合は orphan prune で復旧する
- Undo/Redo はローカル操作のみ対象とし、リモート由来の変更は対象外
- オフライン中の編集は LinkSelf の Store-and-Forward によりオンライン復帰時に自動伝播する

## ズーム制御

- 既定のズームステップ（1.0）は粗すぎるため、より細かい刻みでズームできるようにする
  - とくに最大ズーム付近とその一段下の差が大きすぎる
  - `zoomSnap` / `zoomDelta` を 0.25 程度に設定し、ホイール・ボタン双方で細かく制御できるようにする
- 最大ズームは 19 とする
  - GSI タイルのネイティブ最大は 18 だが、`maxZoom: 19` でわずかにオーバーズーム表示を許容する
  - それ以上の拡大は補間が粗くなり実用性が下がるため採用しない

## 操作ヘルプ（ツールチップ）

- 地図画面を開いた直後、ポリゴン描画関連の操作ヘルプを自動で順次表示する
  - 対象はアプリ特有の操作のみ。ズーム/パン/レイヤ切替などの一般的な地図操作は対象外
  - 区域親番や区域の追加・削除もアイコンで直感的に分かるため対象外
- 実装済みのポリゴン描画操作のみをヘルプに含める。未実装の機能はヘルプに先出ししない
- 表示位置は画面右上、スライドダウンで出現し数秒後にフェードアウト
  - 同時表示は最大 5 件、超過時は最古から即時消去
  - 新しいメッセージは最上段に入り、既存は下へ押し下げる
- 各メッセージには「このメッセージを表示しない」リンクがあり、個別に永続非表示化できる
- 非表示状態は LinkSelf 個人設定に保存（端末間同期）
- 地図画面でのトリガ
  - データロード完了直後: 実装済みの描画操作 7 件を順次表示（セッション中 1 回）
  - ポリゴンの頂点ホバー: 「頂点をドラッグで移動」tip を再表示
  - ポリゴンの辺ホバー: 「辺を右クリックで新しい頂点を追加」tip を再表示
- **仕様・実装変更時は i18n の `tips.map.polygon.*` 文言と齟齬がないか必ず確認する**
- 実装済み対象操作（i18n キー `tips.map.polygon.*`）
  - `startDraw`, `continueVertex`, `confirmDraw`, `cancelDraw`
  - `selectPolygon`, `moveVertex`, `splitEdge`
