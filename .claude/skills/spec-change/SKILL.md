# spec-change — 仕様変更を一貫フローで進める

CODEMAP と実装のずれを「思い出してやる規約」ではなく「手順の固定ステップ」にするための軽量ワークフロー。
**中間ドキュメント（実装計画書・決定記録・進捗サマリ等）は一切作らない**（CLAUDE.md 開発方針に従う）。

## 前提の確認（最初に一度だけ）
- 変更が「バグ修正」なら仕様は変わらないことが多い → wants 改訂は不要な場合あり。「仕様の追加・変更」なら wants 改訂は必須。
- 影響する仕様テーマ（`docs/wants/NN`）を1〜複数特定する。

## 手順（順に実施。各ステップは飛ばさない）

1. **仕様を確定する（SoT）**
   - 変更が仕様に及ぶなら `docs/wants/NN_*.md` の該当箇所を先に改訂する。ここが唯一の正。
   - 純粋なバグ修正で仕様不変なら、このステップはスキップしてよい（その旨を一言残す）。

2. **CODEMAP で実装箇所へ直行する**
   - `docs/CODEMAP.md` の該当テーマ節だけを読み、対象ファイルへ向かう。
   - **コードベース全体の Grep/Glob 探索はしない**（索引に載っていない挙動に触れて初めて探索する）。
   - 索引に穴（記載外のファイル/挙動）を見つけたら、判明した対応をこの後ステップ4でまとめて追記する。

3. **実装する**
   - 対象ファイルを編集。UI を触るなら CLAUDE.md「UI 実装方針」（ネイキッド UI 禁止・既存 class 踏襲・共通ボタン）に従う。
   - テストがある層は TDD（RED→GREEN）で進め、`cd pwa && npm test` が green になることを確認する。

4. **CODEMAP を同期する（このフローの肝）**
   - 変更したファイルについて `docs/CODEMAP.md` を見直す:
     - **新規ファイル** → 該当テーマ節に1行追加
     - **責務が変わった** → その行の説明を修正
     - **削除/リネーム** → 該当行を修正/削除
   - `.d.ts` 等の型シムは索引対象外（仕様に対応しない ambient 宣言）。

5. **i18n 準拠レビュー（UI を触った場合）**
   - グローバル CLAUDE.md「実装後の i18n 準拠レビュー」に従い、編集ファイルの日本語ハードコード混入を確認する:
     ```bash
     grep -nP "[\p{Hiragana}\p{Katakana}\p{Han}]" <file> | grep -v "^\s*\*" | grep -v "^\s*//"
     ```
   - 接尾辞・接頭辞・区切り文字の抜けに注意。混入があれば catalog にキー追加→修正→再テスト。

6. **独立エージェントレビュー（学習型）**
   - コミット前に、実装コンテキストを持たない独立エージェントで変更をレビューする。
     手順・起動プロンプト・学習台帳の運用は `.claude/skills/learned-review/SKILL.md` を SoT とする。
   - Agent ツール（`general-purpose`・同期実行）で起動し、(a) learned-review の SKILL.md と learnings.md、
     (b) `git diff HEAD`、(c) 該当 wants 節（プロンプトに明記して渡す）を読ませ、所見を返させる。
   - **high/med の所見は修正して再テスト**（修正が大きければ再レビュー）。low は対応可否を判断し、
     見送るなら理由をコミットメッセージに残す。
   - **レビュー後に learnings.md を更新する**（実不具合の発見／後日の見逃し発覚→新パターン追記、
     3 回連続 false positive→retired 化）。学習の更新までがこのステップ。

7. **コミットする**
   - `docs/wants/`（変更時）・実装ファイル・`docs/CODEMAP.md` を**同一コミット**にまとめてコミットする。
   - `.githooks/pre-commit` が構造ドリフト（新規/削除ファイルの索引漏れ）を機械検査する。
     意味的ドリフト（責務説明の陳腐化）はステップ4で人手／AI が担保する。
   - コミットメッセージに変更の意図を残す（このプロジェクトは中間ドキュメントを作らず、意図は wants とコミットに集約する）。

## やらないこと
- 実装計画書・設計メモ・進捗サマリ等の中間ファイル生成（禁止）。
- 目的のない全 Grep/Glob（CODEMAP を先に引く）。
- CODEMAP を後回しにして別コミットに分ける（ずれの温床。原則 step7 で同一コミット）。
- レビュー抜きのコミット（軽微な typo 修正等でも step6 は省略しない。学習台帳の照合が目的のため）。
