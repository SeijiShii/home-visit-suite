# learned-review 学習台帳

運用ルールは SKILL.md「学習の更新」。**実際にこのプロジェクトで起きたパターンのみ**を載せる（一般論は書かない）。

## L-001 部分的 i18n ハードコード（接尾辞・接頭辞・区切り）
- 初出: 2026-07 以前 `${displayName}号室` の接尾辞だけハードコードのままコミットし、ユーザー指摘で発覚
- パターン: 大半が catalog 経由でも、テンプレートリテラルの接尾辞/接頭辞/区切り文字だけ生の日本語が残る
- 検査: `grep -nP "[\p{Hiragana}\p{Katakana}\p{Han}]" <編集ファイル>` をコメント行除外で確認
- status: active

## L-002 冪等判定が「存在」だけ見て「同一性」を見ない
- 初出: 2026-07-15 `PairPage.tsx`（`hasIdentity` のみで冪等スルーし、QR の DID とローカル DID を照合せず。別 ID を作成済みの端末が永久に紐づけ不能になった）
- パターン: 「既に有るならスキップ」の冪等分岐で、「有るもの」が期待対象と同一かの照合が抜ける
- 検査: 冪等/スキップ/早期 return 分岐を見たら「何と何の同一性をもって冪等なのか」を diff に問う
- status: active

## L-003 エラー時の誘導先が別の不可逆操作を誘発する
- 初出: 2026-07-15 `PairPage.tsx`（ペアリング失敗→「オンボーディングへ」誘導→独立グループ創設、という事故導線）
- パターン: 失敗時のフォールバック CTA が、失敗原因の解消（再試行・再発行）ではなく別状態の新規作成になっている
- 検査: エラーパスの CTA を「リトライ/原因解消」か「新規作成系」かに分類し、後者なら生成物の独立性・巻き戻し可否を確認
- status: active

## L-004 状態変更後の再配線漏れ（起動時にしか読まれない値）
- 初出: 2026-07-15 `PairPage.tsx`（completePairing 後にリロードせず、bootstrap 時 seed のままの LinkSelf 配線が残った）
- パターン: bootstrap/初期化時にしか読まれない値（seed・networkId・名前空間ポインタ等）を実行中に書き換えて、再読込/再配線をしない
- 検査: localStorage 等への書き込みを見たら「その値はいつ・どこで読まれるか」を確認。起動時のみなら reload/再配線の有無を確認
- status: active

## L-006 対をなす別ストレージの破棄漏れ（localStorage だけ消して OPFS 等が残る）
- 初出: 2026-07-15 `group-slots.ts` purge（localStorage の名前空間キーのみ破棄し、対の OPFS `hvs-group-<slotId>.db` が無期限残存。独立レビューが commit 前に検出）
- パターン: 1 つの論理データが複数ストレージ（localStorage + OPFS/IndexedDB 等）に分かれているとき、破棄処理が片方だけを消す
- 検査: 破棄/削除系の diff では、対象の論理データが載る全ストレージ（CODEMAP・ファイル名導出関数の使用箇所）を列挙して突合。即時削除不能なら孤児記録等の代替があるか確認
- status: active

## L-007 複数所属化の過渡期に残る単一ポインタへの無条件上書き
- 初出: 2026-07-15 `linkself-services.ts` hookedIdStore.set（追加参加で既存スロットの networkId を上書きし別グループのデータが混在し得た。独立レビューが commit 前に検出）
- パターン: 「1 つだけ」前提だった書き込み経路（アクティブポインタ・単一キー）が、複数対応の仕様化後もガード無しで残る
- 検査: 複数所属/複数実体を導入する diff では、旧単一前提のポインタへの set/上書き箇所を grep し、既存値と異なる値が来た場合の分岐が仕様どおりか確認
- status: active

## L-008 新規オーバーレイがコンテンツ内の既存浮遊 UI に z-index で負ける
- 初出: 2026-07-15 `style.css` サイドバーオーバーレイ（z:1000 で追加したが、`.tip-stack` z:9999・`.visit-page-list-button`/`.drawing-toolbar` z:1000 等がコンテンツ側に既存し、同値後勝ち/高値で前面に残った。独立レビューが commit 前に検出）
- パターン: モーダル的なオーバーレイ/backdrop を追加するとき、リポジトリ内の既存 z-index の分布を確認せず低い値を割り当てる
- 検査: オーバーレイ追加の diff では `grep -n "z-index" pwa/src/style.css | sort -t: -k3 -n` で既存最大値を確認し、モーダル層はそれより上に置く。backdrop より上に残ってよい UI か個別に判断
- status: active

## L-009 サイズ上限のある出力経路に可変長データを載せて無言破損
- 初出: 2026-07-15 `QrCode.tsx` × ペアリング payload v2（メンバー数比例で伸びる payload が QR 容量上限 2331B を超えると console.error のみで空白 canvas。独立レビューが commit 前に検出）
- パターン: 出力先（QR・URL 長・プッシュ通知本文等）に固定上限があるのに、載せるデータを可変長に拡張し、超過時のユーザー可視のフォールバックが無い
- 検査: payload/出力データを拡張する diff では、出力経路の上限（QR 容量・URL 実務上限等）と最大想定サイズを見積もり、超過時の可視挙動を確認
- status: active

## L-010 OPFS SAHPool はプールディレクトリ単位で排他（複数 DB 同時 open が衝突）
- 初出: 2026-07-15 増分①の DB 分割（個人 DB+グループ DB の 2 ファイル同時 open で 2 つ目の installOpfsSAHPoolVfs が NoModificationAllowedError → グループ DB が in-memory フォールバックし users が永続されず。**レビュー 2 回とも見逃し・本番でユーザー報告により発覚**）
- パターン: OPFS SAHPool VFS はプールディレクトリ内の全ファイルの Access Handle を排他取得するため、既定プールを共有する複数 worker の同時 open は必ず失敗する。かつ失敗が catch でフォールバックされると**無言でインメモリ化**し永続性だけが消える
- 検査: `SqliteWasmDatabase.open`（または SAHPool install）の呼び出しが 1 実行パスに複数ないか。複数あれば vfsPool（プール分離）指定を確認。catch フォールバックがあるなら「失敗がユーザー/ログからみえるか」も確認
- status: active

## L-005 主体切替時のローカル状態の部分的な持ち越し
- 初出: 2026-07-15 `PairPage.tsx` の別 DID 切替（旧 ID の networkId・グループ名・自己レコードが新 ID 側に残り得る問題を実装時に対処）
- パターン: identity・アクティブグループ等の「主体」を切り替える処理で、主体に紐づくローカルキーの一部だけ破棄し残りが持ち越される
- 検査: 切替系 diff では対象主体に紐づく全ローカルキーを列挙（CODEMAP・`grep -rn "localStorage" 該当層`）して破棄/保持の判断を突合
- status: active
