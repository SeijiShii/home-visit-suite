## L-003 エラー時の誘導先が別の不可逆操作を誘発する

## L-004 状態変更後の再配線漏れ（起動時にしか読まれない値）

- 検査: localStorage 等への書き込みを見たら「その値はいつ・どこで読まれるか」を確認。起動時のみなら reload/再配線の有無を確認
- status: active

## L-007 複数所属化の過渡期に残る単一ポインタへの無条件上書き

- 検査: 複数所属/複数実体を導入する diff では、旧単一前提のポインタへの set/上書き箇所を grep し、既存値と異なる値が来た場合の分岐が仕様どおりか確認

## L-008 新規オーバーレイがコンテンツ内の既存浮遊 UI に z-index で負ける
- 初出: 2026-07-15 `style.css` サイドバーオーバーレイ（z:1000 で追加したが、`.tip-stack` z:9999・`.visit-page-list-button`/`.drawing-toolbar` z:1000 等がコンテンツ側に既存し、同値後勝ち/高値で前面に残った。独立レビューが commit 前に検出）
- パターン: モーダル的なオーバーレイ/backdrop を追加するとき、リポジトリ内の既存 z-index の分布を確認せず低い値を割り当てる
- 検査: オーバーレイ追加の diff では `grep -n "z-index" pwa/src/style.css | sort -t: -k3 -n` で既存最大値を確認し、モーダル層はそれより上に置く。backdrop より上に残ってよい UI か個別に判断
- status: active

## L-009 サイズ上限のある出力経路に可変長データを載せて無言破損
- 初出: 2026-07-15 `QrCode.tsx` × ペアリング payload v2（メンバー数比例で伸びる payload が QR 容量上限 2331B を超えると console.error のみで空白 canvas。独立レビューが commit 前に検出）
- パターン: 出力先（QR・URL 長・プッシュ通知本文等）に固定上限があるのに、載せるデータを可変長に拡張し、超過時のユーザー可視のフォールバックが無い
- 検査: payload/出力データを拡張する diff では、出力経路の上限（QR 容量・URL 実務上限等）と最大想定サイズを見積もり、超過時の可視挙動を確認
- status: active

## L-010 OPFS SAHPool はプールディレクトリ単位で排他（複数 DB 同時 open が衝突）
- 初出: 2026-07-15 増分①の DB 分割（個人 DB+グループ DB の 2 ファイル同時 open で 2 つ目の installOpfsSAHPoolVfs が NoModificationAllowedError → グループ DB が in-memory フォールバックし users が永続されず。**レビュー 2 回とも見逃し・本番でユーザー報告により発覚**）
- パターン: OPFS SAHPool VFS はプールディレクトリ内の全ファイルの Access Handle を排他取得するため、既定プールを共有する複数 worker の同時 open は必ず失敗する。かつ失敗が catch でフォールバックされると**無言でインメモリ化**し永続性だけが消える
- 検査: `SqliteWasmDatabase.open`（または SAHPool install）の呼び出しが 1 実行パスに複数ないか。複数あれば vfsPool（プール分離）指定を確認。catch フォールバックがあるなら「失敗がユーザー/ログからみえるか」も確認
- status: active

## L-011 「自分除外」フィルタが同一アカウントの兄弟端末まで落とす
- 初出: 2026-07-15 link-self groupshare（メンバー配送・catch-up 要求・要求受理・アカウント解決のすべてが「自アカウント除外」で、同一 DID の別端末が配送対象に一度も入らず、ペア済み端末へグループデータが流れなかった。独立レビューが commit 前に検出）
- パターン: 2層 identity（アカウント＋デバイス）で「self を除外する」ルーチンがアカウント単位で書かれ、自アカウントの他デバイスという正当な宛先まで除外される
- 検査: メンバー/宛先列挙・membership 判定の diff では「自分除外」の粒度（アカウントかデバイスか）を問い、兄弟端末が到達可能かをトレース
- status: active

## L-012 後で特権処理される「控えキュー」が主体（ユーザー）に紐づいていない
- 初出: 2026-07-15 `hvs.pendingSiblingDevices`（起動時にユーザー鍵でロスターへ追加署名される控えが、どのユーザー宛かを持たず・切替時の purge 対象にも無く、別ユーザーのデバイスが新ユーザーのロスターに署名混入し得た。独立レビューが commit 前に検出）
- パターン: 「後で信頼付与される待ち行列」（pending/queue/控え）が、付与先の主体と紐づかずに永続され、主体切替後に消費される
- 検査: pending/queue 系キーの diff では (a) エントリが主体（ユーザー DID 等）を持つか (b) 消費側が主体照合するか (c) 主体切替の purge 経路に含まれるか、を確認
- status: active

## L-013 バージョン順序 merge（高い方全面採用）導入時に旧・無バージョンデータの移行が無い
- 初出: 2026-07-15 ロスター rev 化（デプロイ済み旧版の v1 ロスターが unmarshal で rev 0 になり、新規ペア端末の rev 2 ロスターに「高 rev 全面採用」で潰されて既存の兄弟端末が脱落し得た。独立レビューが commit 前に検出）
- パターン: rev/epoch で「高い方が全面勝ち」の merge を導入するとき、既存永続データがバージョン欠落（=0 扱い）のまま残ると、内容の薄い新規ピアの低いが正のバージョンに richer な旧状態が丸ごと潰される
- 検査: 単調 rev・LWW 化する diff では「デプロイ済みの無バージョンデータが load 時に何として扱われるか」「新規作成物の初期値がそれを超えないか」「load 経路に一度きりの移行（再署名/再スタンプ）があるか」を突合
- status: active

## L-014 否定条件（リストからの不在）を失効・削除と解釈する検知の誤爆
- 初出: 2026-07-15 端末削除（「ロスターに自分が居ない＝削除された→全初期化」の判定が、ペアリング直後の正当な過渡状態＝発行側の高 rev ロスターがまだ新端末を学んでいない、で確定誤爆し新端末が即ワイプされる経路。独立レビューが commit 前に検出。tombstone=明示的失効記録の導入で修正）
- パターン: 「リストに無ければ削除とみなす」型の検知は、未収束・ブートストラップ過渡の正当な不在と意図的な削除を区別できない。破壊的アクション（ワイプ・購読解除・BAN）のトリガーには明示的な否定記録（tombstone）が要る
- 検査: 「〜が無ければ削除/失効とみなす」分岐を見たら、(a) その不在がブートストラップ/マージ過渡で正当に発生しないか (b) 明示シグナル（tombstone 等）に置き換えられないか (c) union 系 merge が削除を復活させないか、を問う
- status: active

## L-015 Leaflet ベクタ層の重なりを一回きりの bringToFront/bringToBack で固定
- 初出: 2026-07-16 `map-renderer.ts` 親番境界線（追加時のみ bringToFront したが、renderAll・差分再描画がポリゴン層を remove→再 add すると境界線が輪郭の下に沈む。独立レビューが commit 前に検出。専用ペイン=createPane+zIndex 固定で修正）
- パターン: Leaflet の同一ペイン内 z 順は DOM 追加順のため、bringToFront/bringToBack は「その時点」の順序しか保証しない。後から同ペインへ layer が再 add される経路（全再描画・modified 再構築）で順序が崩れる
- 検査: bringToFront/bringToBack を含む diff では、同ペインへ layer が後から add される経路を列挙し、順序が再確立されるか・専用ペイン（createPane + zIndex）で代替できるかを問う
- status: active

## L-016 @media 上書きを同一セレクタのベース規則よりソース順で前に書いて無効化
- 初出: 2026-07-16 `style.css` `.checkouts-list-panel`（狭幅上書きの @media ブロックをベース規則より前に挿入し、同一詳細度の後勝ちでベースが常に適用＝上書きが死んでいた。独立レビューが commit 前に検出）
- パターン: メディアクエリは詳細度を上げないため、同一セレクタの上書きはベース規則より後ろに無いと効かない。追記位置が既存ベース定義より前だと無言で無効化される
- 検査: @media 追加の diff では、上書き対象セレクタのベース定義行番号と @media ブロックの行番号を `grep -n` で比較し、media が後にあることを確認
- status: active
