# learned-review — 学習型の独立エージェントレビュー

実装者（メインエージェント）のバイアスから独立した目で、コミット前の変更を検査する。
**学習型**: このプロジェクトで実際に起きた不具合パターンを `learnings.md`（このディレクトリ）に蓄積し、
レビューのたびに必ず全件照合する。レビューを重ねるほど検査が濃くなる。

## 起動方法

### A. spec-change ステップ6から（通常経路）

メインエージェントが Agent ツール（`general-purpose`、**同期実行** `run_in_background: false`）で
独立エージェントを起動する。プロンプトテンプレート:

```
あなたは home-visit-suite の独立コードレビュアーです。実装の経緯や会話コンテキストは意図的に与えられていません。
1. /home/seiji/home-visit-suite/.claude/skills/learned-review/SKILL.md の「レビュー手順」と、同ディレクトリの learnings.md（全件）を読む
2. リポジトリ /home/seiji/home-visit-suite で `git diff HEAD` と `git status --short` により未コミット変更を読む
3. この変更の仕様 SoT は <docs/wants/NN_*.md の該当節をここに明記> 。仕様と diff を突合する
4. レビュー手順に従い検査し、所見を以下の形式のみで返す（前置き・要約不要）:
   [high|med|low] <file>:<line> — <所見> / 再現: <具体シナリオ> / learning: <該当 L-ID or なし>
   所見が無ければ "no findings" とだけ返す
```

- メイン側は **high/med を修正して再テスト**（修正が大きければ再レビュー）。low は対応可否を判断し、
  見送るなら理由をコミットメッセージに残す。
- **レビュー後に「学習の更新」（下記）を必ず実施する。学習の更新までがレビューステップ。**

### B. 手動（/learned-review）

現在の未コミット変更（引数でコミット範囲指定も可）を対象に、自分自身で「レビュー手順」を実行する
（独立性は落ちるが台帳照合は同じ）。引数に範囲があれば `git diff <範囲>` を対象とする。

## レビュー手順（レビュアー側）

1. **learnings.md を全件読む**（必読。ここが他の汎用レビューとの差分）
2. 変更 diff と、diff が触る各ファイルの周辺コードを読む
3. **台帳照合**: 各 learning の「パターン」「検査」を diff に当てる。検査コマンドがあれば実行する
4. **汎用観点**（台帳に無くても見る）:
   - 正確性: 境界値・エラーパス・処理順序・非同期の競合
   - 仕様整合: 指定された wants 節の記述と diff の挙動が一致するか（仕様に無い挙動・仕様の読み落とし）
   - テスト妥当性: 追加テストが仕様を検証しているか（実装の写経になっていないか）・既存挙動の回帰
   - プロジェクト規約: CLAUDE.md「UI 実装方針」（ネイキッド UI 禁止等）・CODEMAP 同期・i18n
5. **憶測の指摘はしない**: 再現シナリオを具体的に書けない所見は報告しない
   （false positive は台帳と運用の信頼を毀損する。確信が持てない場合は low + その旨明記）

## 学習の更新（メインエージェント側・レビュー後に必ず）

`learnings.md` を以下のルールで更新する:

- **新パターン追記**: レビューが実不具合を発見した／レビュー後にユーザーから不具合報告があった（=見逃し）
  場合、そのパターンを追記する。形式:
  ```
  ## L-NNN <一行タイトル>
  - 初出: <日付> <ファイル/事象>
  - パターン: <どういう構造の間違いか（このプロジェクトの文脈で）>
  - 検査: <diff にどう当てるか。可能なら機械的コマンド>
  - status: active
  ```
- **一般論は書かない**: 「実際にこのプロジェクトで起きた」ものだけを載せる（台帳の照合コストを守る）
- **retire**: 同じ learning が 3 回連続 false positive を出したら `status: retired` に変える（行は削除しない。復活可）
- 台帳はこのスキルの唯一の永続状態。`docs/` 配下には置かない（中間ドキュメント禁止原則とは別枠の
  `.claude` 配下ツール状態として扱う）

## やらないこと

- 会話コンテキストをレビュアーに渡す（独立性が目的。仕様 SoT の節参照だけを渡す）
- 台帳に無い一般論チェックリストの網羅列挙（汎用観点は4項に限定）
- 所見ゼロを恐れた水増し指摘（"no findings" は正当な結果）
